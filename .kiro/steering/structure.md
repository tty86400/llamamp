# Structure

```
llamamp/
├── main.go                  # entry: window, service binding, 20 Hz push loop
├── audio/                   # engine package — no UI concerns leak in here
│   ├── decode.go            # sources (mp3/wav) + `normalized` format chain
│   ├── spectrum.go          # ring buffer, FFT, 32 log bands, peak caps
│   └── engine.go            # oto context, transport state machine, EOF watcher
├── src/                     # frontend (Vite + TypeScript)
│   ├── main.ts              # rendering + user actions; subscribes to `tick`
│   ├── mygo.ts              # GENERATED by `mygo generate` — never edit
│   └── style.css            # classic Winamp base skin, all CSS, no images
├── index.html               # shell: player panel + playlist panel
├── mygo.config.ts           # MyGo app config (name, version, window defaults)
├── mise.toml                # pins go 1.27.4 + bun 1.3.5
└── .kiro/                   # steering, specs, hooks (see below)
```

## Layering rules

- `audio/` must not import `mygo` or touch the DOM. It is a library:
  pure PCM in, transport state out. `main.go` bridges it to the UI.
- The frontend talks to Go only through `src/mygo.ts` calls and the
  `tick` event. No fetch, no websockets.
- If `mygo generate` would change a hand-edited file, the Go comments
  changed shape — fix the comment, not the generated file.

## Where things go

- New decoder format (flac/ogg): new file in `audio/` implementing the
  `source` interface, one case in `openSource`.
- New UI element: add to `index.html`, style in `style.css`, wire in
  `main.ts`. The canvas visualizer is the only thing drawing every frame.
- Kiro assets: steering docs in `.kiro/steering/`, feature specs in
  `.kiro/specs/<feature>/` (requirements/design/tasks), automation in
  `.kiro/hooks/*.json`.
